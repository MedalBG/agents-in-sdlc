GitHub Copilot をエージェントモードにすると、コードベースを調べ、変更を提案してファイルを編集し、コマンドを実行するなど、自律的に作業します。VS Code の Copilot Chat では、ツール呼び出しやファイル編集の状況をリアルタイムで確認できます。差分をインラインでレビューして個々の変更を採用または取り消し、エディターを離れずに追加のプロンプトで会話を誘導し、作業を調整または拡張できます。

この演習では、次の作業を行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして採用します。
- セッションの途中でエージェントを誘導し、ハイコントラストに加えてライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントが、ハイコントラストモードを実装しています。作業中、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加してほしいとのことです。新しい会話を最初から始める代わりに、既存のセッションを誘導して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集など、各ステップが表示されます。ファイル編集は差分と **Keep** / **Undo** の操作付きでチャットにインライン表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイル編集を提案すると、差分がインライン表示されます。
   - 変更を採用するには **Keep** を選択します。
   - 変更を取り消してエージェントに再度試させるには **Undo** を選択します。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ツール呼び出し (たとえばターミナルコマンドの実行) の許可を求められると、エージェントは一時停止して **Allow** を表示します。実行してもよいコマンドだけを許可してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に、変更内容を要約するメッセージが表示されます。

## エージェントを誘導してライトモードを追加する

ハイコントラストモードができたら、同じ会話を続けてライトモードの切り替えを追加します。同じチャットセッションを使うため、エージェントは先ほどの作業で変更したコンポーネント、採用したスタイル、設定したローカルストレージのパターンなどのコンテキストを保持しています。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を調べて、ライトモードの追加を提案します。
3. 変更が提案されるたびに、ハイコントラストモードと同じようにレビューします。各差分で **Keep** または **Undo** を選択します。
4. エージェントが意図しない方向に進んだ場合 (たとえば、トグルの UI を望まない形でリファクタリングしようとした場合) は、チャット入力欄の横にある **Stop** で停止してから、追加の説明を送信します。

> [!TIP]
> 作業中のセッションを誘導する方が、最初からやり直すよりも速く済みます。追加プロンプトで調整 (「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使ってください」)、方向修正 (「3 つ目のトグルは追加せず、既存の設定パネルにライトモードを組み込んでください」)、または範囲の拡張 (「両方のトグルにキーボードショートカットも追加してください」) を依頼できます。

## 変更内容をレビューする

コミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティパターン (ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージへの保存) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、進行中のセッションを監視し、誘導しました。ファイル編集を確認して採用または取り消し、コンテキストを失わずに追加プロンプトを送り、作業を拡張しました。

このレッスンでは、次の作業を行いました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を採用または取り消す。
- 作業中のセッションに追加プロンプトを送って誘導する。

[次のレッスン][next-lesson]では、アクセシビリティ対応の変更を pull request として公開し、このラボを通じてローカルのカスタムエージェントが行った変更をレビューします。
