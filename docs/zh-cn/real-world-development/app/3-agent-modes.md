我们刚刚为项目添加了一项小功能，但更复杂的更改需要更完善的流程。GitHub Copilot app 可融入组织现有的工作流，帮助我们用正确的方法构建正确功能。本课将开启一系列课程，带你体验典型的智能体驱动开发流程：从议题开始开发功能，确认代码有效、功能符合预期，最终成功合并到项目中。

> [!NOTE]
> 后续功能工作将沿用同一会话。通常，不同文件类型的工作会使用不同会话或 PR；本研讨会为了聚焦核心概念而简化了流程。

本课将介绍如何：

- 根据 GitHub 议题开始新的智能体会话。
- 使用 **Plan** 模式明确需求。
- 使用 **Autopilot** 模式实现新功能。
- 审查代码。
- 在浏览器画布中手动验证功能。

继续开发该功能时，你还会更新存储库指令、自定义现有的 quality-checks 技能、添加 MCP 验证、创建 QA 智能体，并打开功能 PR。

## 场景

Tailspin Toys 的目录不断扩大，访问者需要按类别和发行商筛选游戏。待办议题描述了该功能，但组合类别等细节需要在编码前确定。你将使用 Plan 模式解决这些问题，然后授权 Autopilot 在明确范围内实现功能。

## 背景

在开发流程中引入 AI 编码智能体并不会改变基本原则，反而使这些原则更加重要。大多数开发者的流程大致如下：

1. 打开已创建的议题，查看需要完成的工作详情。
2. 制定要构建内容的计划。
3. 编写并审查代码。
4. 运行测试以验证代码。
5. 手动验证新功能。
6. 创建拉取请求 (PR)。
7. 代码通过审查且持续集成流程成功后，合并代码。

> [!NOTE]
> 具体流程因团队和组织而异，但大多与上述流程类似。

遵循这种标准方法，可以确保 AI 生成的代码满足需求，并像手写代码一样经过审查。

## 会话模式

**会话模式**决定智能体拥有多少自主权。可以从提示框下方的下拉列表中设置模式，并随时更改：

- **Interactive**：你与智能体协作。智能体提出变更建议，并等待你的输入后再继续。
- **Plan**：智能体先创建计划。你审查并批准计划后，智能体才会执行。
- **Autopilot**：智能体完全自主工作，包括编写代码、运行测试和迭代，无需等待输入。

先在 Plan 模式中审查计划，再使用 Autopilot 实现。

## 从议题启动会话

开始筛选工作前，确认星级评分 PR 已合并，并且本地 `main` 已更新。

1. 在侧边栏的 **Sessions** 下，选择 Tailspin Toys 存储库文件夹，然后在存储库顶部导航中选择 **Issues**。打开 **Allow users to filter games by category and publisher**。这是已有的预置议题，无需再创建。
2. 选择 **New session**，并选择基于更新后 `main` 的 **new working tree**。

    ![GitHub Copilot app 的议题视图中指向 New session 按钮的箭头](../../../_images/app-new-session-from-issue.png)

3. 确认议题已附加到会话，并在模式选择器中选择 **Plan**。

> [!NOTE]
> 如果找不到 Node.js 或 npm，让智能体运行 `node --version` 和 `npm --version`。如果它们能在终端运行但不能在会话中运行，请检查应用的 PATH 或版本管理器设置，然后完全退出并重新打开应用。重试失败的操作和检查；不要仅因智能体找不到 npm 就重新安装 npm。

## 规划筛选功能

规划让你可以在 Copilot 编写代码前审查方案。由于会话从议题启动，Copilot 已获得功能请求的上下文。发送：

```plaintext
Build this feature.
```

回答 Copilot 的问题，并将计划与议题验收标准进行比较。确认计划涵盖类别和发行商筛选、无障碍控件、数据访问变更和测试。讨论尚不明确的行为，例如多个类别如何组合，或没有游戏匹配时应如何处理。

计划应使用项目现有工具运行 lint、单元测试、E2E 测试和类型检查。将范围限定为实现和测试筛选功能；完成质量工作流后再创建 PR。批准前请修改计划中不合适的部分，并保留议题 URL 和双方确认的澄清内容，供后续验证使用。

## 明确批准 Autopilot

满意后，选择 **Approve and implement this plan**，或当前版本中等效的选项。不要假定批准计划会自动切换模式；确认活动模式指示器显示 **Autopilot**。

Copilot 会开始实现功能，按计划逐步生成代码、运行测试并迭代。

> [!NOTE]
> 批准后可能会立即开始实现，因此请先审查计划。如果 Copilot 报告缺少依赖项或端口冲突，请先解决设置问题，再将检查视为已完成。只停止自己启动的服务器。

## 审查并验证实现

代码生成后，和其他代码一样，必须在合并前审查。现在检查代码并运行网站，确认一切正常。

1. 打开 **Changes**，检查筛选功能实现和测试。
2. 对照议题和已确认的澄清内容检查结果，包括多个类别和发行商的组合；确认变更符合现有存储库指令。
3. 检查 lint、单元测试、E2E 测试和类型检查的输出。跳过的检查不能算通过。
4. 接受实现前解决失败项，并重新运行受影响的检查。Playwright 的 E2E 配置会构建并提供预览服务，也可能复用本地服务器；确认被测服务器属于此工作树，而不是之前课程启动的服务器。

## 探索新功能

代码看起来不错，但能否正常运行？像之前一样启动应用，并在浏览器画布中打开网站。

1. 使用以下提示，让 Copilot 启动应用并在浏览器画布中打开页面：

    ```plaintext
    Start the app and open it in the browser canvas.
    ```

2. 稍等片刻，应用将启动，Copilot app 内会打开浏览器窗口。
3. 选择一个类别并确认结果符合该类别。清除筛选，再选择一个发行商并确认结果符合该发行商。
4. 组合类别和发行商筛选，并根据议题和已批准的计划检查结果。如果支持多个类别，还要验证已约定的组合行为。
5. 测试一个没有匹配游戏的筛选组合并检查空状态。清除或重置筛选，确认完整列表恢复。
6. 完成后，使用以下提示让 Copilot 停止为此会话启动的开发服务器，并关闭浏览器画布：

    ```plaintext
    Stop the dev server and close the browser canvas.
    ```

## 在后续课程中保留此会话

现在不要创建或合并筛选 PR。后续第 4 到第 8 课会继续使用此会话、工作树和分支。下一课会将自定义指令应用于筛选代码，然后添加技能和 QA 改进，最后在第 8 课创建并合并合并后的 PR。停止开发服务器后，可以让会话保持空闲，并在下一课返回同一会话。

## 总结和后续步骤

你使用不同的智能体模式构建并审查了功能。本课中，你：

- 根据 GitHub 议题开始新的智能体会话。
- 使用 **Plan** 模式明确需求。
- 使用 **Autopilot** 模式实现新功能。
- 审查代码。
- 在浏览器画布中手动验证功能。
